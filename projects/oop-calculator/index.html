    How it’s built

    • Inheritance: each operation extends the abstract Operation class and supplies its own symbol and apply() method. Adding a new operation means adding a subclass, without changing the calculator.
    • Encapsulation: Calculator keeps its state in private fields. The interface can only press keys and read the display, so the state can’t become inconsistent.
    • Separation of concerns: the Swing CalculatorPanel (and this web page) only forward key presses, so the user interface can be replaced without touching the arithmetic.
    • Tested: the same behaviours are checked in Java (CalculatorTest) and JavaScript, including left-to-right chaining, rounding and division by zero.
